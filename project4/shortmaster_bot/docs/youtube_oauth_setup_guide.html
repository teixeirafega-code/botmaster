ShortsMaster Bot YouTube OAuth Setup Guide

This guide sets up YouTube OAuth for ShortsMaster Bot without uploading anything. The safe validation command uses channels.list(mine=true) to detect the authenticated channel, compare it with the configured channel, and confirm credentials work.

Project Paths

  • Project root: C:\Users\tgt\Desktop\botmaster\project4\shortmaster_bot
  • OAuth client secret: secrets\youtube_client_secret.json
  • OAuth token: secrets\youtube_token.json
  • Config file: config.yaml
  • Safe channel validation command: python -m app.main youtube-auth-check
  • Pre-upload safety checklist: python -m app.main pre-upload-checklist

1. Confirm Live Upload Safety Stays Off

Keep live upload disabled while setting up OAuth.

$env:PAPER_MODE="true"
$env:ENABLE_REAL_UPLOAD="false"
$env:LIVE_UPLOAD_ENABLED="false"
python -m app.main pre-upload-checklist

The checklist should show real_upload_allowed: false. This is expected and safe.

Real uploading requires PAPER_MODE=false, ENABLE_REAL_UPLOAD=true, LIVE_UPLOAD_ENABLED=true, a configured channel_id, per-video approved_for_live_upload=true, OAuth credentials, quota availability, and duplicate checks.

2. Create a Google Cloud Project

  1. Open the Google Cloud Console: https://console.cloud.google.com/
  2. Sign in with the Google account that owns or manages the YouTube channel.
  3. Open the project selector at the top of the page.
  4. Select New Project.
  5. Use a clear name, for example ShortsMaster Bot.
  6. Create the project and make sure it is selected.

3. Enable YouTube Data API v3

  1. In the selected Google Cloud project, open APIs & Services -> Library.
  2. Search for YouTube Data API v3.
  3. Open the API page.
  4. Click Enable.
  5. Open APIs & Services -> Enabled APIs & services and confirm the API is listed.

4. Configure the OAuth Consent Screen

  1. Open APIs & Services -> OAuth consent screen.
  2. Choose External for normal public/testing use, or Internal only for a Google Workspace organization.
  3. Set app name to ShortsMaster Bot.
  4. Set user support and developer contact email.
  5. Add scopes:
    • https://www.googleapis.com/auth/youtube.upload
    • https://www.googleapis.com/auth/youtube.readonly
  6. If the app is in testing mode, add the Google account that owns the channel as a test user.

Use OAuth for YouTube. Service accounts are not supported for normal YouTube account access.

5. Create OAuth Credentials

  1. Open APIs & Services -> Credentials.
  2. Click Create Credentials.
  3. Select OAuth client ID.
  4. Application type: Desktop app.
  5. Name: ShortsMaster Bot Local.
  6. Click Create.
  7. Download the JSON file.

6. Save youtube_client_secret.json

New-Item -ItemType Directory -Force -Path .\secrets

Move or rename the downloaded OAuth client file to:

C:\Users\tgt\Desktop\botmaster\project4\shortmaster_bot\secrets\youtube_client_secret.json

Confirm config.yaml points to the same paths:

publishing:
  youtube_client_secrets_file: secrets/youtube_client_secret.json
  youtube_token_file: secrets/youtube_token.json
  oauth_mode: local_server

Do not commit the secrets directory.

7. Generate youtube_token.json

cd C:\Users\tgt\Desktop\botmaster\project4\shortmaster_bot
$env:PAPER_MODE="true"
$env:ENABLE_REAL_UPLOAD="false"
$env:LIVE_UPLOAD_ENABLED="false"
python -m app.main youtube-auth-check

The command loads the client secret, confirms it is a Desktop App credential with a top-level installed section, archives stale tokens when the OAuth client changes, starts run_local_server(port=0) if a fresh token is needed, writes secrets\youtube_token.json, and calls channels.list(mine=true) to detect the authenticated channel. It does not upload a video.

8. Detect and Configure the Channel

After OAuth succeeds, the command prints the authenticated channel ID and title:

{
  "authenticated_channel_id": "UCxxxxxxxxxxxxxxxxxxxxxx",
  "authenticated_channel_title": "Your Channel Name",
  "configured_channel_id": "",
  "matches_configured_channel": false,
  "upload_attempted": false
}

Copy the channel ID and title into config.yaml:

publishing:
  channel_id: "UCxxxxxxxxxxxxxxxxxxxxxx"
  channel_name: "Your Channel Name"

Run python -m app.main youtube-auth-check again. The expected result is "matches_configured_channel": true.

9. Validate Connection Without Uploading

python -m app.main youtube-auth-check
python -m app.main pre-upload-checklist

Validation passes when the channel is returned, matches_configured_channel is true, upload_attempted is false, and the pre-upload checklist still shows real_upload_allowed: false while live flags are off.

The channels.list method with mine=true retrieves channels owned by the authenticated user and has a quota cost of 1 unit.

10. Troubleshooting

Client secret file not found

Check that secrets\youtube_client_secret.json exists and matches config.yaml.

missing required parameter: redirect_uri or redirect_uri_mismatch

Create credentials as Desktop app. If you used a web client, create a new desktop OAuth client and replace the JSON file. Confirm publishing.oauth_mode is local_server. If you replaced the OAuth client, delete or let the bot archive the old secrets\youtube_token.json before trying again.

Wrong channel detected

Delete secrets\youtube_token.json, rerun python -m app.main youtube-auth-check, and sign in with the correct Google account.

11. Live Upload Readiness Checklist

python -m app.main pre-upload-checklist --queue-id <QUEUE_ID>

Required checks include disabled paper mode, real upload flags, channel ID, OAuth files, per-video live approval, duplicate protection, daily upload availability, YouTube quota availability, and video file existence.

python -m app.main approve-live <QUEUE_ID>
